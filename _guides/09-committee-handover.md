# 09 – Committee handover checklist

Do this **every year after the AGM**, when a new committee takes over. It takes about 30 minutes. If it gets skipped, the site can become impossible to update once the old committee graduates.

Do it **together**: one outgoing and one incoming committee member, sitting together.

---

## The accounts that matter

| Account | What it controls | Who should have access |
|---|---|---|
| **CES GitHub account** (`cairns-engineering-society`) | Owns the website repository. Adds/removes editors and changes settings. | Login held by the President (+ one other committee member as backup) |
| **CES Google account** (`cairns.engineering.society@gmail.com`) | The "CES Events" Google Calendar, Google Forms and responses, CES Google Drive | Committee |
| **Editors' personal GitHub accounts** | Editing the site | Whoever on the committee will update the site |

**Where the logins are kept:** [PLACEHOLDER: e.g. a restricted "Logins" document in the CES Google Drive, or a password manager]. **Never in this repository.**

## Checklist

### GitHub

- [ ] New committee members who'll edit the site have **their own GitHub accounts** (free at [github.com/signup](https://github.com/signup)).
- [ ] Add them as editors. See [10 – Adding or removing an editor](10-adding-or-removing-an-editor.md).
- [ ] **Remove** outgoing members who no longer need access (same guide).
- [ ] Hand over the **CES GitHub account login** to the new President (or whoever will hold it):
  - [ ] Change the password and store the new one in the logins location above.
  - [ ] **Two-factor authentication (2FA):** GitHub requires a code from an authenticator app when you sign in. Move the 2FA to the new holder's phone: sign in as CES → profile picture → **Settings** → **Password and authentication** → set up the authenticator app again on the new phone.
  - [ ] Check the **recovery codes** are saved in the logins location. Without these, a lost phone can mean losing the account forever. Regenerate them on the same settings page if unsure.
  - [ ] Check the email address on the CES GitHub account is the **CES email**, not a personal one.

### Google

- [ ] Change the CES Google account password if it was shared with outgoing members.
- [ ] **Calendar:** check who has "Make changes to events" on the CES calendar (calendar settings → **Shared with**). Add new members and remove old ones.
- [ ] **Forms:** check the suggestion, event suggestion, subject review and testimonial forms are still open and responses are going to the CES account.

### Website content

- [ ] The **About** page (`about.md`) lists committee **roles only, not names**, so it doesn't need updating each year. Only change it if the constitution changes the roles.
- [ ] Update the **contact details** on the About page if they changed.
- [ ] Check **Past events** on the Events page (`events.md`) is up to date, and that the **regular events** descriptions still match what CES runs.
- [ ] Look through the **event suggestions** form responses with the new committee.
- [ ] Upload the AGM minutes to the **Documents** page if they're public (see [03 – Uploading a file](03-uploading-a-file.md)).
- [ ] Update the **constitution** PDF if it changed.
- [ ] Skim each page for anything out of date (old dates, broken links). Check the [Discord invite link](https://discord.gg/rsNMRNq7uh) still works.
- [ ] **Placement page:** check it against the current Engineering Professional Practice Handbook on LearnJCU and update its "Last checked" line. Check the rules in `files/Service-and-Leadership-Hours-Log-Template.xlsx` still match.
- [ ] **New JCU handbook:** check the subject pages and `degree.md` against the new year's handbook. See [04 – Adding a subject](04-adding-a-subject.md#each-new-year-updating-for-the-new-handbook).

### Knowledge

- [ ] The incoming editor reads [00 – How this site works](00-how-this-site-works.md) and [01 – Editing a page](01-editing-a-page.md), then makes one small edit while the outgoing member watches.
- [ ] Record below who did the handover.
